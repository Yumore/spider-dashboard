# 内容源集成与统一入口（2026-11-01）

## 需求

在宿主中集中接入已迁入的动漫、小说、视频、漫画、直播、媒体播放和网页采集逻辑，让用户从统一入口按内容类型进入真实业务页面，并让源目录和书源管理遵循宿主现有的 UI 样式。

## 现状

各领域代码已有宿主入口：

| 类别 | 现有逻辑 | 本轮接入方式 |
| --- | --- | --- |
| 动漫 | `animeEntryCatalog`：AnimeOne、TakoPlay、天使动漫论坛、AnimeTrace | 直接纳入统一分类页 |
| 小说 | `novelEntryCatalog`、Legado 书源、EasyMyGo、ESO | 增加书源管理与规则阅读入口 |
| 视频 | `movieEntryCatalog` 中的影视站点、榜单、下载和短视频 | 直接纳入统一分类页 |
| 漫画 | `comicEntryCatalog` 中的本地书架及在线漫画源 | 直接纳入统一分类页 |
| 直播 | `liveEntryCatalog` 中的 Billd、我的电视和 EasyTV | 直接纳入统一分类页 |
| 媒体 | 共享 `MediaPlaybackPage` 播放服务 | 增加 HTTP(S) 直连地址表单并复用播放器 |
| 采集 | `CrawlerModulePage` 任务、解析、日志和导出流程 | 直接纳入统一分类页 |

原内容中心按模块分入口，源页面样式分散。小说源管理只从书架工具栏进入；通用媒体播放器没有 URL 输入入口。

来源卡片复用 `ContentEntrySectionView` / `ContentEntryCard`，页面标题栏、留白、卡片圆角与输入框复用 `ModulePageScaffold` 和 `ContentTokens`。统一路由也会给来源页及其后续子页面应用 `ContentPageTheme`。阅读器和视频播放器保留各自适合沉浸阅读/播放的专用界面。

## 实施

- 新增 `SourceLibraryPage` 与分类目录，从内容中心增加“内容源库”入口；分类页引用现有模块目录并调用原有页面构造器，保持来源注册、网络加载、收藏/书架、播放和采集逻辑继续由原业务模块负责。
- 小说模块增加 Legado 书源管理、EasyMyGo、ESO 与书源阅读入口；书源管理的导入、启用/禁用、删除和书架入口沿用既有仓库与持久化实现。
- 媒体分类增加 HTTP(S) 直连地址表单，校验协议/主机后打开共享播放器；地址不持久化，也不写入日志。无内嵌播放能力的平台隐藏入口并显示兼容提示。
- 抽取 `ContentPageTheme` 并由公共 `openContentPage` 路由和 `ModulePageScaffold` 共同应用，给已接入的源页、后续子页面和共享目录统一卡片圆角、层次与输入框密度。
- 书源管理改用共享页面骨架、卡片、加载失败/空状态样式和统一间距。
- 本轮没有复制新的第三方代码、升级依赖或导入新远程源列表。既有来源许可记录保留在 `document/licenses/`；网站内容与用户输入的源地址由各自服务方提供，应用不为其内容版权作保证。

## 验证与边界

- `dart format` 覆盖本轮 10 个 Dart 文件，无格式变更未保存。
- 新源库、媒体页面、目录与共享 UI 文件定向 `dart analyze` 通过。
- 书源管理页面定向分析受本机 Pub 缓存缺失 `dio` 包影响，报告了该现有导入对应的 5 项解析错误；代码执行未能完成该页面的完整静态检查。
- 未运行测试、未执行真实网站请求、未构建 APK 或其他平台包，也未做设备 UI 验收。
- 新入口只是把现有模块的真实路由集中到统一目录；来源站点可用性、响应结构、媒体地址有效性和第三方服务变动仍由目标服务决定。
